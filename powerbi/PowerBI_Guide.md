# Power BI Dashboard Guide

Power BI Desktop (`.pbix`) files are binary and can't be authored directly by
this project's scripts — this guide gives you everything needed to build the
dashboard in a few minutes: which tables to load, the DAX measures, and a
suggested page layout.

## 1. Get data

Use **Get Data → Text/CSV** (or connect directly to your SQL database if
you've loaded `sql/01_schema.sql`) and import:

- `data/raw/zones.csv`
- `data/raw/consumption_daily.csv`
- `data/raw/weather_daily.csv`
- `data/raw/leakage_incidents.csv`
- `data/raw/billing_monthly.csv`
- `data/raw/pipe_network.csv`
- `data/processed/demand_forecast_test_predictions.csv` (generated by the Python model)
- `data/processed/leak_anomaly_flags.csv` (generated by the Python model)

## 2. Model relationships

Build a star schema:

- `zones[zone_id]` → 1-to-many → `consumption_daily[zone_id]`
- `zones[zone_id]` → 1-to-many → `weather_daily[zone_id]`
- `zones[zone_id]` → 1-to-many → `leakage_incidents[zone_id]`
- `zones[zone_id]` → 1-to-many → `billing_monthly[zone_id]`
- `zones[zone_id]` → 1-to-many → `pipe_network[zone_id]`

Add a **Date table** (Modeling → New Table) and relate it to `consumption_daily[date]`,
`weather_daily[date]`, and `billing_monthly[billing_month]`:

```dax
DateTable = CALENDAR (DATE(2023,1,1), DATE(2025,12,31))
```

## 3. Core DAX measures

```dax
Total Billed (ML) =
DIVIDE ( SUM ( consumption_daily[billed_consumption_liters] ), 1000000 )

Total Production (ML) =
DIVIDE ( SUM ( consumption_daily[production_volume_liters] ), 1000000 )

NRW % =
DIVIDE (
    [Total Production (ML)] - [Total Billed (ML)],
    [Total Production (ML)]
)

Per Capita Consumption (L/day) =
DIVIDE (
    SUM ( consumption_daily[billed_consumption_liters] ),
    SUM ( consumption_daily[population_est] )
)

YoY Demand Growth % =
VAR CurrentYearTotal = [Total Billed (ML)]
VAR PriorYearTotal =
    CALCULATE ( [Total Billed (ML)], SAMEPERIODLASTYEAR ( DateTable[Date] ) )
RETURN
    DIVIDE ( CurrentYearTotal - PriorYearTotal, PriorYearTotal )

Revenue at Risk =
SUM ( billing_monthly[revenue_expected] ) - SUM ( billing_monthly[revenue_collected] )

Avg Collection Rate % =
AVERAGE ( billing_monthly[collection_rate] )

Leak Incidents (Count) =
COUNTROWS ( leakage_incidents )

Estimated Water Lost (ML) =
DIVIDE ( SUM ( leakage_incidents[estimated_volume_lost_liters] ), 1000000 )

Flagged Anomaly Days =
CALCULATE ( COUNTROWS ( leak_anomaly_flags ), leak_anomaly_flags[is_anomaly] = TRUE )

Forecast MAPE % =
AVERAGEX (
    demand_forecast_test_predictions,
    DIVIDE (
        ABS ( demand_forecast_test_predictions[billed_ML] - demand_forecast_test_predictions[predicted_ML] ),
        demand_forecast_test_predictions[billed_ML]
    )
)
```

## 4. Suggested pages

**Page 1 — City Overview**
KPI cards (Total Billed ML, NRW %, Avg Collection Rate %, Leak Incidents),
a line chart of daily billed vs. production volume, a map of zones sized
by population, a YoY growth trend.

**Page 2 — Demand Forecasting**
Line chart overlaying `billed_ML` (actual) vs. `predicted_ML` (forecast) from
`demand_forecast_test_predictions.csv`, a card showing `Forecast MAPE %`, and
a scatter of temperature vs. consumption to show weather sensitivity.

**Page 3 — Leakage & Infrastructure Risk**
Bar chart of estimated water lost by zone, a table of pipe segments filtered
to `age_years > 40` or high-risk material, and a matrix of anomaly-flagged
days per zone (from `leak_anomaly_flags.csv`) with conditional formatting.

**Page 4 — Revenue & Billing**
Revenue at Risk by zone, Avg Collection Rate % trend by month, and a
zone-level table combining NRW % with collection rate to prioritize
intervention (high NRW + low collection = highest priority).

## 5. Design tips

- Use a consistent blue/teal palette for water volume, red/orange for
  loss & risk metrics, and green for efficiency/collection metrics.
- Add a zone slicer and a date-range slicer synced across all pages.
- Use conditional formatting (icon sets) on the NRW % and Collection Rate %
  tables to make outlier zones pop at a glance.
